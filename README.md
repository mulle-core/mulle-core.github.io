# mulle-core.github.io

Landing page for the [mulle-core](https://github.com/mulle-core/mulle-core)
amalgamated C library.

- **Live site:** https://mulle-core.github.io/
- **Stack:** plain HTML + CSS. No JavaScript, no build step, no dependencies.
- **Social preview:** `images/mulle-core-preview.jpg` (1200×675) is used for the
  Twitter/OpenGraph card (`summary_large_image`).

## Files

| File                            | Purpose                                       |
|---------------------------------|-----------------------------------------------|
| `index.html`                    | Single-page landing (semantic HTML + JSON-LD) |
| `style.css`                     | All styling and animations (dark "lava" theme)|
| `images/mulle-core-preview.jpg` | Social preview card (1200×675)                |
| `LICENSE`                       | BSD-3-Clause (carried over from the old site) |
| `.nojekyll`                     | Disables Jekyll so the static HTML is served  |
| `.github/workflows/semgrep.yml` | Semgrep CI                                    |
| `README.md`                     | This file                                     |

## Preview locally

Just open `index.html` in a browser. It is plain HTML + CSS with no build step,
and the relative links (`style.css`, `images/…`) resolve from the file system.

## Deploy

For an organization GitHub Pages site, this repository must be named
`mulle-core.github.io` under the `mulle-core` org, and Pages is served from
the `master` branch root by default — no workflow needed.

The repository must be **public** to publish on the free org plan. This
history is unrelated to the original site's history (which is preserved on the
`legacy-site` branch); publish with a force push.

```sh
git add index.html style.css images README.md LICENSE .nojekyll \
        .github/workflows/semgrep.yml
git commit -m "mulle-core landing page"
git push --force github master
```

The pre-existing site (`index.md`, `_config.yml`, `LICENSE`, semgrep workflow)
is kept on the `legacy-site` branch.

## Keeping content fresh

- The module grid lists the constituents. When the amalgamation gains or loses
  a constituent, update it there.
- The social preview card is a headless-Chromium screenshot of the hero, resized
  to 1200×675 and saved as `images/mulle-core-preview.jpg`. Regenerate it after
  noticeable visual changes:

  ```sh
  chromium-browser --headless --no-sandbox --disable-gpu --hide-scrollbars \
     --window-size=1200,675 --screenshot=/tmp/preview.png \
     "file://$PWD/index.html"
  convert /tmp/preview.png -resize 1200x675 -quality 90 images/mulle-core-preview.jpg
  ```
- Two things live outside this repository and are linked from several places:
  the developer guide *De Re mulle-core* at
  `https://www.mulle-kybernetik.com/de-re-mulle-core` (nav, hero, `#guide`
  section, footer) and the `mulle-core-demo` example programs at
  `https://github.com/mulle-core/mulle-core-demo` (`#demos` section, footer).
  Update them here if either URL changes.
- The GitHub org profile renders
  [`mulle-core/.github`](https://github.com/mulle-core/.github)
  `profile/README.md`, whose stack banner is generated by
  `generate-stack-svg.sh` from an inline constituent list. When the module set
  changes here, add the constituent there (and in that repo's `README.md`
  tables), rerun `./generate-stack-svg.sh`, and commit the regenerated
  `profile/*.svg`.
- The quick-start snippets must match the real APIs in
  `<mulle-core/mulle-core.h>` — verify signatures against the amalgamated
  headers before editing code blocks.
